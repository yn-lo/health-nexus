# RAG 检索-生成流程技术规范

> 适用范围：health-nexus 后端 RAG 引擎（医学科普知识库问答）。本规范描述从用户提问到 AI 回复的完整流程、可配置参数、安全防线、降级机制与可观测性设计。文档以自然语言与流程描述表达，不包含代码片段。

---

## 1. 概述

### 1.1 目标

RAG（Retrieval-Augmented Generation）流程是 health-nexus 医院健康宣教平台的核心能力，通过检索增强生成技术为患者提供 7x24 智能健康问答。系统围绕已审核发布的医学科普知识库，将检索到的可信切片作为上下文注入大语言模型，使回答具备可溯源的资料支撑，承担"减轻医护重复宣教负担"与"保证患者获得严肃化健康指导"的双重职责。

### 1.2 核心原则

- **可溯源**：每条 AI 回复均附带命中的知识库切片引用（章节、文章标题、相关度分数），患者可追溯结论来源。
- **严肃化**：医疗场景下，系统对回答边界有严格约束——不诊断、不开处方、不建议停药；信息不足以回答时坦诚告知而非编造。
- **宁可拒答不可乱答**：当检索结果为空、相似度过低或被判定为知识库外问题时，系统主动拒答而非强行生成，避免幻觉对患者造成误导。这是贯穿全流程的最高优先级安全准则。
- **关键失败明确报错**：Embedding 调用失败时（唯一不可降级的检索关键依赖），系统向上返回错误，chat 域按拒答路径处理（写入 assistant 拒答消息），而非静默退化到仅关键词检索。Rerank 失败、LLM 流失败等其他依赖均安全降级。

## 2. 流程阶段

RAG 流程从患者提交提问开始，到 SSE 推送完成回复结束，共分为七个阶段。阶段之间存在严格的顺序依赖与短路退出机制：任一安全审查不通过或检索阶段判定拒答时，后续阶段不再执行。

### 阶段 1：输入安全审查

用户消息在进入检索流程前需通过两层安全审查，确保不合规输入在零延迟规则层被拦截，疑似违规输入由 LLM 复核。

**1a. 消息长度与空值校验**

- 空消息直接拒绝（消息内容不能为空）。
- 单条消息字符数（按 UTF-8 rune 计）超过上限（2000 字符）时拒绝，避免超长输入冲击下游模型上下文窗口。

**1b. 紧急症状预提醒**

- 对消息执行紧急症状关键词检测（如胸痛、呼吸困难、自杀倾向等）。
- 命中时在 SSE 流起始阶段下发 `safety_warning` 事件，提醒患者立即就医。
- 此提醒为附加性提示，不阻断后续流程；同一流程内若已下发紧急提醒，后续的拒答事件不再重复推送 `safety_warning`，避免双重告警造成前端困惑。

**1c. 规则层安全审查（零延迟）**

- 基于配置的敏感词与安全规则进行匹配，覆盖自杀自伤、紧急症状、Prompt 注入三大类别。
- 命中危机关键词时进入危机处理路径：持久化用户消息与危机事件、下发心理援助热线话术、SSE 推送 `crisis` 事件并以 `done=[DONE]` 终止流。即使事务持久化失败，仍向患者推送热线信息，确保救命信息送达。
- 命中 Prompt 注入类规则时进入拒答路径：持久化用户消息与拒答 assistant 消息（结果码 `REJECTED`），下发拒答话术后终止流。

**1d. LLM 就绪性预检与 LLM 深度审查**

- 调用 LLM 前先检测服务可用性，不可用时返回"AI 服务暂不可用"。
- LLM 深度审查作为规则层疑似复核：对疑似不合规但未被规则层明确拦截的输入进行二次判断。审查拒绝时进入拒答路径，结果码标记为 `INTERCEPTED`（深度拦截），区别于规则层的 `REJECTED`。

### 阶段 2：查询改写

多轮对话中，用户当前提问常为指代性或省略性表述（如"那个副作用持续多久"）。查询改写阶段将当前提问结合历史对话压缩为可独立检索的完整问句。

**2a. 历史消息加载与裁剪**

- 加载当前会话最近 N 轮历史消息（默认 5 轮，即 user + assistant 各 5 条），并排除当前轮用户消息（当前轮已在阶段 1 持久化，避免上下文中出现两条连续 user 消息）。
- 改写阶段的 Token 预算兜底：估算"历史消息 + 当前查询"的总 token 数，超过改写场景 token 上限（4000）时按 FIFO 顺序丢弃最早历史轮次，直到满足预算或历史不足两轮。token 估算按字符类别加权（中文 1.5、英文字母 0.25、数字与符号 0.5、空格不计），近似真实 tokenizer 行为以避免突破模型上下文窗口。

**2b. 改写调用**

- 将当前提问与历史消息传入改写模型，生成独立问句。
- 改写失败时降级为原始查询，不影响后续流程（降级优先而非中断）。匿名用户（无会话历史）跳过历史加载，直接对原始消息执行改写。

### 阶段 3：知识库检索

混合检索阶段，并发执行向量检索与全文检索，再通过 RRF 融合与可选 Rerank 得到最相关的知识库切片。

**参数解析**：优先使用请求携带的 top_k，其次使用全局 RAG 配置，最后使用系统默认值（5）。检索候选数取 top_k 的 2 倍以为融合与重排留余量，但不超过 max_chunks 上限与硬上限（50）。

**3a. 向量检索（pgvector ANN）**

- 调用 Embedding 模型将改写后的查询转为查询向量。
- 在 PostgreSQL 的 pgvector 索引上执行 HNSW 近邻检索（余弦距离），返回候选切片。
- 相似度分数为 `1 - cosine_distance`，因 Embedding 已归一化，分数落在 [0, 1] 区间。
- **SQL 层阈值预过滤**：当 similarity_threshold > 0 时，在 SQL `WHERE` 子句中直接以 `1 - (embedding <=> query) >= similarity_threshold` 过滤，减少低质候选回传与上层重复计算。
- SQL 同时排除空内容切片（`content != ''`）、非发布状态文章、已软删除文章，并按科室可见性过滤（本科室文章 + 已授权引用给本科室的文章）。
- **Embedding 失败时向上返回错误**：Embedding 是检索的唯一不可降级依赖。生成查询向量失败时，SearchSimilarChunks 直接向上返回 error，chat 域按"检索失败降级拒答"路径处理（写入 assistant 拒答消息保证会话完整性），而非静默退化到 BM25-only 路径。BM25 仍然作为混合检索的第二路信号参与 RRF 融合（embedding 正常时），与向量检索互补。

**3b. BM25 全文检索（PostgreSQL bigram ts_rank）**

- 在文章切片的 tsvector 列上执行全文检索，查询词经中文 bigram 分词后以 OR 语义匹配。
- 相关性分数为 PostgreSQL `ts_rank`，量纲与向量相似度不同，由后续 RRF 融合时归一化。
- 同样排除空内容、非发布、软删除切片，并按科室可见性过滤。
- 单路失败不阻塞另一路（降级为空命中）。

**3c. RRF 融合（Reciprocal Rank Fusion）**

- 对向量路与全文路结果按排名计算 RRF 分数：`score = 1 / (k + rank)`，其中 rank 从 1 起算，常数 k 取标准值 60。
- 同一切片在两路都命中时分数累加；向量路的原始相似度分数（VecScore）取两路中的较大值保留。
- 两路均为空时直接返回空结果，触发后续拒答。

**3d. 相似度阈值过滤**

- 对融合后的结果按 VecScore 过滤，仅保留 VecScore >= similarity_threshold 的命中。
- **医疗场景不豁免 BM25-only 命中**：VecScore 为 0（仅全文路命中、无向量证据）的切片一律过滤，避免无向量语义支撑的低质结果混入回答上下文。
- threshold <= 0 时不过滤（保留全部），此为关闭阈值过滤的配置方式。
- 过滤后结果为空时直接返回空切片，触发拒答。

**3e. Rerank 重排（可选，安全降级）**

- 截断到 top_k 后，若配置启用 Rerank 且 Rerank 依赖已注入，对候选切片调用 Rerank 模型重排。
- Rerank 按模型返回的相关性分数排序，并按 rerank_threshold 过滤低分结果（threshold <= 0 时不过滤）。
- Rerank 调用失败或返回空时降级为原 RRF 顺序，不中断流程。
- Rerank 依赖未注入（如未配置 Rerank provider）时静默跳过，保持检索结果稳定。

**可选 MMR 多样性重排**：若配置了 diversity_factor > 0，在 Rerank 之后执行最大边际相关性重排，平衡相关性与结果多样性。lambda = diversity_factor，取值 0 为纯相关性（保持原顺序），1 为纯多样性。文档间相似度用 Jaccard 词集相似度近似（无需额外 embedding）。lambda > 1 时截断为 1。

### 阶段 4：检索结果安全检查

检索返回后，在进入 LLM 生成前执行三道安全检查，任一不通过即走拒答路径。

**4a. 空内容过滤**

- 在提取切片内容构造 LLM 上下文时，对每个切片内容执行 TrimSpace 判断，过滤空字符串与纯空白内容，避免空切片混入生成上下文。

**4b. OOD 知识库外检测**

- 统计所有命中切片中的最大 VecScore。
- 当最大 VecScore 低于 OOD 阈值（默认 0.3，范围 0.0 ~ 0.5，管理员可在管理端调整）时，判定为知识库外问题——即便检索有结果，语义相关度仍不足以支撑可信回答，系统主动拒答。
- 此阈值与可配置的 similarity_threshold（0.75）作用不同：similarity_threshold 控制单切片准入门槛，OOD 阈值是更低的"是否属于知识库覆盖领域"的绝对下限。OOD 注入一道独立于单切片过滤的语义边界防御，避免检索器勉强返回的低相关度切片误导 LLM 生成。
- 设为 0 时关闭 OOD 检测，所有检索结果均可进入生成阶段（不推荐）。过高（如 > 0.4）可能导致正常问答被误判为知识库外问题。
- 命中 OOD 时记录告警日志并走拒答路径。

**4c. 无检索结果拒答**

- 检索调用失败（非降级空结果）或检返返回 0 条切片时，直接走拒答路径。
- 阶段 1 已持久化的用户消息若直接返回 503 会留下无 assistant 回复的孤儿消息污染会话历史，因此降级为写入 assistant 拒答消息保证会话完整性，并记录原始错误供排查。

### 阶段 5：LLM 流式生成

通过安全检查后，将检索切片作为上下文注入 LLM 执行流式生成。

**5a. 生成阶段 Token 预算兜底**

- 生成器输入 = 系统提示词 + 历史消息 + 当前查询 + 检索切片。
- 针对"历史 + 查询"按生成场景 token 上限（16000）再次 FIFO 裁剪历史（改写阶段已按 4000 裁剪一次，此处针对更宽松的生成预算二次确保）。

**5b. 系统提示词构造**

- 优先使用数据库中配置的 active system prompt；provider 不可用或返回空时降级为硬编码默认提示词（7 条规则，见第 5 节）。
- 降级静默进行，配置域故障不应导致 chat 流程不可用。

**5c. 流式调用与 token 推送**

- LLM 流式调用加 per-request 硬截止时间（4 分钟），与防并发锁 TTL（5 分钟）对齐，留 1 分钟余量给收尾事务与 SSE flush，避免 LLM 服务 stall 导致 goroutine 与连接泄漏。
- 每个 token 先成功推送 SSE `token` 事件再累积到本地缓冲，确保缓冲仅含客户端已收到的 token，中断路径的持久化内容与客户端实际所见一致。
- LLM 流正常结束但未产生任何 token 时（如服务返回空流），显式将占位消息终结为拒答话术 + `REJECTED`，避免空 content 以 `ANSWERED` 落库。
- 流式过程中若发生错误：已输出部分 token 时标记为已完成（避免覆盖已生成内容），返回 503；未输出任何 token 时走拒答路径。
- 超时检测：客户端断开（父 ctx 取消）时提前返回不做无效输出审查；streamCtx 超时（LLM stall）时，空内容走拒答并返回 503，有部分内容则标记为部分答案（`PARTIAL`）并推送截断提示。

### 阶段 6：输出安全审查

LLM 生成完成后，对累积的完整答案执行输出侧安全审查。

- 审查结果分两种：拦截（越权内容替换为安全话术）与追加免责声明。
- SSE `safety_warning` 事件携带 `mode` 与 `text`：`mode=replace` 时前端用完整安全话术覆盖已累积的 token 缓冲；`mode=append` 时前端将声明追加到答案末尾。如此 UI 最终内容与 DB 持久化内容保持一致。
- 审查通过时不推送任何事件。

### 阶段 7：结果落库 + SSE 推送

- 在事务内终结 AI 占位消息：写入最终答案、引用切片列表、结果码（`ANSWERED` / `INTERCEPTED` / `PARTIAL`）。
- 结果码规则：输出审查拦截为 `INTERCEPTED`；LLM 超时导致不完整为 `PARTIAL`；正常完成为 `ANSWERED`；各类拒答为 `REJECTED`；危机为 `CRISIS`；规则层注输入拦截为 `INTERCEPTED`。
- 引用切片在推送阶段以 `references` 事件下发裸数组（与 token 事件穿插），供前端展示可溯源引用。
- 最终推送 `done=[DONE]` 事件标记流结束。
- 中断路径（ctx 取消、LLM 错误）有 defer 清理逻辑：用独立超时的 `context.Background()` 执行（请求 ctx 可能已取消），流已完成时对完整内容做输出审查后落库真实答案，流未完成时将占位消息终结为拒答避免孤儿空消息。

## 3. 配置参数说明

RAG 参数为单例配置（数据库固定 id=1 的记录），由医护端配置页面维护，范围校验与后端 CHECK 约束一致。配置不可用时全部参数回退到默认值。

| 参数 | 默认值 | 范围 | 作用说明 |
|------|--------|------|----------|
| chunk_size（切片大小） | 500 | 200 ~ 2000 | 文章切片时单切片的字符数上限。影响检索粒度与上下文密度——过小丢上下文，过大稀释相关性。 |
| chunk_overlap（切片重叠） | 50 | 0 ~ 500 | 相邻切片重叠字符数，避免语义在切片边界被截断。必须小于 chunk_size（前端与后端均校验）。 |
| max_chunks（最大切片数） | 10 | 1 ~ 50 | 检索候选数上限，避免大 top_k 时检索过多候选切片冲击 Embedding/Rerank 性能与 LLM 上下文窗口。 |
| top_k（检索数量） | 5 | 1 ~ 50 | 最终返回给 LLM 生成的切片数量。候选数（top_k * 2）在融合与重排后截断到此值。 |
| similarity_threshold（相似度阈值） | 0.75 | 0.0 ~ 1.0 | 向量相似度准入门槛，VecScore 低于此值的切片被过滤。设为 0 关闭过滤（保留全部）。医疗场景不豁免仅 BM25 命中（VecScore=0）的切片。 |
| rerank_enabled（启用 Rerank） | true（检索服务兜底默认）/ false（数据库默认） | 布尔 | 启用后对融合结果调用 Rerank 模型重排。关闭时忽略 rerank_threshold 与 diversity_factor。Rerank 依赖未注入时静默降级跳过。 |
| rerank_threshold（Rerank 阈值） | 0.5 | 0.0 ~ 1.0 | Rerank 后按此阈值过滤低分结果。设为 0 关闭过滤。仅在 rerank_enabled=true 时生效。 |
| diversity_factor（多样性因子） | 0 | 0.0 ~ 1.0 | MMR 多样性重排的 lambda 权重。0 为纯相关性（保持原顺序），1 为纯多样性。仅在 > 0 时生效，> 1 截断为 1。 |
| ood_threshold（OOD 阈值） | 0.3 | 0.0 ~ 0.5 | 知识库外检测的绝对最低 VecScore 下限。最大 VecScore 低于此值即判定为知识库外问题并拒答。独立于 similarity_threshold 的语义边界防线。设为 0 关闭检测。过高可能导致正常问答被拒。管理员可在管理端 RAG 参数配置中调整。 |

> 注：数据库 SQL DEFAULT 为 false，但 seed 数据与检索服务的兜底默认值均为 true（以提升检索质量，Rerank 依赖未注入时安全降级跳过）。实际生效值以数据库读取为准。

## 4. 质量防线总览

RAG 流程设置 7 道防线，从切片生成到提示词约束形成完整防御链，任一道不通过即拒答或降级，避免低质或越权内容触达患者。

1. **切片准入防线**：检索 SQL 层排除空内容切片（`content != ''`）、非发布状态文章、软删除文章，并按科室可见性过滤（本科室 + 已授权引用），从源头保证候选切片的合法性与可见性。

2. **双路检索融合防线**：向量检索（语义）与 BM25 全文检索（关键词）并发执行后 RRF 融合，兼顾语义匹配与术语精确命中。Embedding 是唯一不可降级的关键依赖——失败时直接返回错误而非静默退化到仅关键词检索。

3. **相似度阈值过滤防线**：对融合结果按 VecScore >= similarity_threshold 过滤，且不豁免 BM25-only（VecScore=0）命中，避免无向量语义证据的低质切片混入。

4. **OOD 知识库外检测防线**：所有切片最大 VecScore 低于 0.3 时拒答，独立于单切片过滤的语义边界防御，避免检索器勉强返回的低相关度切片误导生成。

5. **无结果拒答防线**：检索失败或返回 0 条切片时降级为拒答（写入 assistant 拒答消息保证会话完整性），而非强行生成或抛 503 留孤儿消息。

6. **系统提示词约束防线**：7 条规则注入 LLM，约束其不得诊断/开处方/建议停药、紧急症状提醒就医、信息不足坦诚告知、不得凭空生成、禁客套话、无关内容拒答（详见第 5 节）。

7. **输出安全审查防线**：对完整答案执行输出侧审查，越权内容替换为安全话术（mode=replace），或追加免责声明（mode=append），确保 UI 与 DB 内容一致。

## 5. 系统提示词规则

默认系统提示词（DB 无 active 配置时的硬编码兜底）定义了 7 条约束 LLM 行为的规则，是回答质量与安全边界的最后一道软约束：

1. **角色定位**：身份限定为医院健康宣教助手，仅能基于提供的参考资料回答患者问题。

2. **禁止越权医疗行为**：不得诊断、开处方或建议停药。

3. **紧急症状处置**：若患者描述紧急症状，提醒立即就医。

4. **信息不足坦诚告知**：信息不足以回答时坦诚告知，不得编造。

5. **禁止凭空生成**：不得凭空生成结论，所有结论需基于参考资料。

6. **禁止客套话**：直接回答问题，不得以"好的""收到""很高兴为您服务"等客套话开头，不得重复用户问题。

7. **无关内容拒答**：若参考资料与用户问题无关或无实质信息，不得基于参考资料作答，应坦诚告知暂无相关资料，不得将无关内容强行关联作答。

**格式规范补充**（附加于规则之后）：
- 使用 CommonMark Markdown 语法，手机端阅读优先。
- 列表最多一层，禁止嵌套子列表；需分类时用加粗小标题加冒号引出，下接平铺要点。
- 顺序/步骤用有序列表，并列要点用无序列表，不要在有序列表内再嵌套无序列表。
- 每条要点尽量一行，超长就拆条。

## 6. 可观测性

RAG 流程在各关键节点输出结构化日志（slog），便于排查检索质量、降级触发与 OOD 判定。

**RAG search detail 日志**（检索阶段末尾）：
- 候选切片数量（融合后、阈值过滤后）
- 生效的 similarity_threshold
- 实际使用的 top_k
- rerank 是否实际启用（`rerank_enabled` 与 `rerank 依赖注入`的合取）

**RAG chunk detail 日志**（转换为最终切片时）：
- 切片序号（rank，从 1 起算）
- chunk_id
- VecScore（向量路原始相似度）
- RRFScore（融合分数）
- content_len（切片内容长度）

**OOD 检测日志**（命中时告警）：
- chunk_count（命中切片总数）
- ood_threshold（生效的 OOD 阈值）

**其他关键日志节点**：
- 改写失败/降级、历史裁剪（改写阶段与生成阶段分别记录前后轮数）、检索失败降级、空检索结果拒答、Embedding 失败（检索返回 error）、Rerank 失败降级、向量/全文单路失败、空 LLM 流降级拒绝、LLM 流超时（部分内容场景）、输出安全审查触发/通过、系统提示词来源（db/default）、流式开始/结束（历史轮数、切片数、token 数、耗时毫秒）、请求完成结果码。

## 7. 安全降级机制

降级原则贯穿全流程：关键依赖缺失或调用失败时降级为拒答或回退到下一可用层，而非抛出中断性错误，保证患者侧交互的连续性与"宁可拒答不可乱答"语义。

### 7.1 Rerank 未配置时降级

- 配置 rerank_enabled=false 或 Rerank provider 未注入时，检索服务跳过 Rerank 步骤，直接以 RRF 融合顺序返回。
- Rerank 调用失败或返回空时，回退为原 RRF 顺序，不影响后续流程。
- 静默降级，不向 chat 域返回错误。

### 7.2 Embedding 失败时（不可降级）

- Embedding 是检索流程中唯一不可降级的关键依赖。向量语义匹配是医疗问答可信度的基石，BM25 关键词匹配无法替代语义理解（如"肚子不舒服"与"腹部隐痛"的语义对应）。
- Embedding 调用失败或返回空时，SearchSimilarChunks 直接向上返回 error，chat 域按"检索失败降级拒答"路径处理：写入 assistant 拒答消息保证会话完整性、记录原始错误供排查、返回拒答话术而非静默退化。
- 此设计确保医疗场景下"宁可明确告知暂时不可用，也不假装搜过了然后说没有"。
- Embedder 依赖完全未注入时（启动阶段），检索服务整体降级返回空切片，chat 域走无检索结果拒答路径。

### 7.3 LLM 超时降级

- LLM 流式调用设 4 分钟硬截止时间，覆盖服务 stall，避免 goroutine 与连接泄漏。
- 截止时间触发时区分两种情况：
  - 空 content：标记流未完成，走拒答路径将占位消息终结为拒答话术，返回 503。
  - 部分内容：标记为 `PARTIAL`，推送截断提示让患者知晓答案不完整，正常落库部分答案。
- LLM 服务就绪性预检不可用时，直接返回"AI 服务暂不可用"，不进入流式调用。
- LLM 流式调用返回错误时：已输出 token 标记已完成避免覆盖，未输出 token 走拒答，统一返回 503。
- 中断路径（ctx 取消、LLM 错误）的 defer 清理使用独立超时的 `context.Background()`，因请求 ctx 可能已取消，用原 ctx 清理会因 context.Canceled 失败而留下孤儿占位消息。

### 7.4 配置不可用降级

- RAG 配置读取失败或返回空时，全部参数回退到兜底默认值（与数据库 SQL DEFAULT 对齐），检索流程继续。
- 系统提示词 provider 不可用或返回空时，降级为硬编码默认提示词（7 条规则），保证 chat 流程不因配置域故障而不可用。
